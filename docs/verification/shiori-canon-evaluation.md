# 本物の設定との矛盾判定: 誤検出の修正

## 変更内容

旧 `evaluate.ts` は、主語とrelationが一致してobjectが異なると、本物の設定の上書きと判定していた。RAGの設定に `did` が含まれると「試験に合格した」と「メモを落とした」のような別の行動まで矛盾になり、再生成後も同じ理由で定型文に置き換わっていた。

`claims.ts` の判定ルールを `contradictionReason(Triple, Triple)` に切り出し、本物の設定と既存の嘘の両方で使うようにした。

- `identity / origin / lives_in / first_appeared` は単一値。同じ主語について違う値を肯定すれば矛盾。
- 同じ三つ組の肯定と否定は矛盾。
- `likes / dislikes`、`can / cannot` は同じ対象について両方肯定すれば矛盾。
- `did` の別の行動、`has` の別の持ち物、複数の属性などは共存できる。
- CanonFactは肯定の三つ組として扱う。自由記述relationは、閉じた語彙と正規化後に一致するときだけ照合する。説明文から新しい関係・否定を推測しない。
- 本物の設定に対する明確な矛盾は1件でも差し戻す。旧実装の「矛盾した主張の割合が0.3を超えたときだけ」という条件を廃し、他の主張で薄めて通ることを防いだ。スコア自体は集計用に残す。
- 差し戻し理由には、矛盾する本物の設定の説明と判定理由も含める。

生成プロンプト・モデル・追加枠は前の修正のまま。新しいLLM呼び出しやプロンプト上の判定手順は追加していない。

## 検証3: 実会話の変更前後比較（各23ターン完了）

```sh
GEMINI_MODEL=gemini-3.5-flash-lite SHIORI_COMPARE=evaluate SHIORI_INTERVAL_MS=5500 SHIORI_FIXTURE=scripts/fixtures/shiori-room-kentei.json node --env-file=.env.local scripts/check-shiori-room.mjs --live --conversation-only
```

`SHIORI_COMPARE=evaluate` は変更前の `evaluate.ts` だけを `e38df88` から取り出し、生成・追加枠・パイプラインなどは両条件で現在のコードを使う。各24ターン、同じユーザー発話列を送り、実際の生成結果をそれぞれの履歴に引き継ぐ。RAG・話題切り替え・としおも実行する。DBは検証用ディレクトリに隔離する。

各24ターンを予定し、23ターンずつ・計46返答を完了した。24ターン目で `gemini-3.5-flash-lite` の1日500回制限に達したため、最後の1ターンずつは未実行。同じモデルで比較できた23ターンを集計する。

初回、同じ「検定に落ちた／合格したところの話がしたい」に対して:

- 旧判定は「……そこはちょっとうまく思い出せない。別のところの話、聞かせて。」に置き換えた。
- 新判定では「あのとき、ハチワレは試験の席でずっと消しゴムを落としそうになっていたね。結果的に合格したけれど、ちいかわは悔しそうだった。」が通った。

20ターン目、勉強の場面へ戻ったときも:

- 旧判定は同じ定型文に置き換えた。
- 新判定は16ターン目に導入したメモ用紙に触れて、勉強の場面の話を続けた。22・23ターン目にも新しい嘘を保存した。

新判定で会話全体の品質が保証されたわけではない。7ターン目には「今日は何について話したい……?」という冒頭に戻る返答があり、ルーターは感想の「怖い」を別の場面への切り替えと捉えた。主張の新規保存件数には既存の言い直しも混じる。後半は履歴と資料が条件ごとに分岐するため、自然さや主張数の差をすべて判定コードの単独効果とは扱わない。

一方、前節の73件の同一入力再検査は、モデルの再生成を挟まずに判定だけの影響を確認している。今回の修正で、生成できていた返答を不必要に定型文へ変えていた経路を解消できた。

APIは計109回を試行（判定役・資料係・埋め込み・としおを含む）。6ターン後に判定役が503を返して停止したが、保存済みのユーザー発話を再利用して7ターン目から再開した。もう1件のエラーは最後の日次上限429。日次上限は再試行せず、比較モデルも途中で替えていない。

## 検査の限界

これは構造化された主張に対する整合検査で、自然言語全般の真偽判定ではない。関係の分類が間違っている、別の行動を同じ三つ組に潰している、主張がclaimsに記録されていない、作った設定をcanonと記録した、といった場合は正確に検査できない。資料取得・話題切り替えの誤りも今回の修正対象には含めない。
